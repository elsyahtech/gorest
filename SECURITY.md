# Security Policy

## Reporting a Vulnerability

Please report suspected security vulnerabilities in GOREST privately through
[GitHub Private Vulnerability Reporting](https://github.com/elsyahtech/gorest/security/advisories/new),
which is enabled for this repository.

Do not report security vulnerabilities through public GitHub issues, discussions,
or pull requests. A public report may expose users before a fix is available.
If private reporting is unavailable, contact the maintainers through a
non-public channel listed on the repository profile; do not include exploit
details or sensitive data in a public post.

When possible, include:

- The affected GOREST version, commit, or branch.
- The component and configuration involved, including relevant database or
  driver details.
- The security impact and the conditions required to reproduce it.
- Minimal reproduction steps or a proof of concept that does not access or
  modify other people's data.
- Any known workaround or mitigation.

Please avoid including real credentials, personal data, production data, or
other secrets in a report. Use redacted examples or disposable test data.

## Response and Disclosure

The maintainers will review the report, may ask for additional information, and
will coordinate with the reporter on a fix and disclosure where the issue is
confirmed. We aim to acknowledge reports within five business days, but this is
an objective rather than a guaranteed response time.

Please allow reasonable time for investigation and a fix before disclosing
details publicly. Once a fix is available, the maintainers may publish a GitHub
Security Advisory describing the impact, affected versions, fixed versions, and
mitigations. A CVE may be requested when appropriate. Reporting a suspected
issue does not by itself mean that a vulnerability has been confirmed.

## Supported Versions

Security fixes are prioritized for the latest released version. Whether older
versions can be fixed depends on the issue and maintenance capacity; upgrade to
the latest release when possible. Check the relevant release notes and GitHub
Security Advisories for security updates.
